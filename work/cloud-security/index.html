Cloud Security

Five Azure builds, each starting from a problem a real business actually has — deployed for real, evidenced, then destroyed.

Most cloud portfolio projects are a virtual machine and a screenshot. These aren't that. Each one starts from a business problem someone would pay to solve, gets built as real infrastructure, and gets a security layer that reflects how it would actually need to run.

Everything is defined in Terraform, so the whole environment is reproducible from source and destroyed the moment the evidence is captured.

Method

How each build runs

A two-loop workflow that keeps the cost near zero without giving up a real deployment.

Loop 1
Local development

Azurite for storage, Azure Functions Core Tools for the real Functions runtime, containerized SQL Server, and a local model behind an OpenAI-compatible endpoint. Iterate and break things freely at zero cost.

Loop 2
Real deployment

terraform apply against Azure free tier, exercise the system under realistic conditions, then capture evidence: architecture diagram, screenshots, logs, cost report, and Defender for Cloud findings.

Loop 3
Teardown & write-up

terraform destroy, confirm nothing is left billing, then write what the build actually taught me — including what failed the first time.

Why local emulation isn't enough on its own. Azurite doesn't support blob versioning, soft delete, lifecycle policy, or immutability — which is the entire substance of project 02. Cost data, Azure Monitor, managed identity, RBAC, and Defender for Cloud have no emulator at all. The local loop is for iteration speed; the real deploy is what makes the work honest.
The series

Five builds

01
Cost Visibility Dashboard

Owners can't read, predict, or explain their cloud bill. I've watched a $5K estimate turn into $30K. This dashboard reports on the genuine spend generated by the four builds below — real billing data, not a mock feed.

Cost Management · Budgets · Monitor alerts · Logic Apps · Workbooks

Security layer: Anomaly detection on spend, budget guardrails, and least-privilege access to billing data.

Azure Queued
02
Automated Backup System

A backup that depends on someone remembering is not a backup — it's a hope. Versioning, lifecycle tiering, immutability against ransomware, and a daily confirmation that proves the thing actually ran.

Blob Storage · Versioning · Lifecycle policy · Immutability · Logic Apps

Security layer: WORM immutability, soft delete, private endpoints, and a restore drill that proves recovery works.

Azure Building
03
Website Uptime Monitor

The site goes down and the owner finds out from a customer complaint. Three independent checks, alerting within seconds, and a dashboard that shows whether reliability is trending the right way.

Timer-triggered Functions · Email/SMS alerting · Workbooks

Security layer: Managed identity instead of stored secrets, and alert logic that resists false-positive fatigue.

Azure Queued
04
Customer Inquiry Manager

As a business grows, leads and urgent requests get buried in the inbox. An LLM categorizes and prioritizes them, then routes automatically — which means untrusted text reaches a model that can take action.

App Service · Azure OpenAI · SQL · Logic Apps

Security layer: Prompt injection defense, output validation, PII handling, and blast-radius limits on what the model may trigger.

Azure Queued
05
AI Inventory Tracker

Businesses run out of hot items or tie up cash in dead stock, making the call on gut instead of data. Real-time stock levels plus predictive restock recommendations.

App Service · SQL · Azure OpenAI

Security layer: Data governance on business records, model abuse monitoring, and guarding against poisoned inputs.

Azure Queued
