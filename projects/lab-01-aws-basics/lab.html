Lab 01 · Fundamentals

Your local AWS environment

~30 minutesNo prior AWS neededCosts nothing

You have a fake AWS running on your Mac. It speaks the same language as the real thing — same commands, same responses — but it lives in Docker, costs nothing, and you cannot break anything that matters.

This lab teaches you how to talk to it. By the end you will have created storage, put a file in it, made it public, seen why that is dangerous, and locked it back down.

That last part is the whole point: lab 02 is a real breach investigation, and it assumes everything here.

Part 1 — What am I actually running
1

Check it is running

Terminal
docker ps
You should see a line likelocal_aws_floci floci/floci:latest Up 2 hours (healthy) 0.0.0.0:4566->4566/tcp
What this meansA container called local_aws_floci is running and listening on port 4566. That port is your fake AWS.
Not running?cd ~/local-aws-test && docker compose up -d
2

Open the console

Browser
Go here
http://localhost:4500/cloud-explorer/aws/storage
What you are looking atA web UI for your fake AWS. The sidebar lists services — Storage is S3, Identity is IAM, SQS is queues. It shows what exists but it cannot change much.
Two different ports4500 is the web console you look at. 4566 is the API your commands talk to. Do not mix them up.
Part 2 — Talking to it from the terminal
3

Set up your shortcut

Terminal

Normally aws talks to Amazon. You need to tell it to talk to your Mac instead, every single time, with --endpoint-url http://localhost:4566.

That gets old fast, so make a shortcut called awslocal.

echo 'alias awslocal="AWS_ACCESS_KEY_ID=test AWS_SECRET_ACCESS_KEY=test AWS_DEFAULT_REGION=us-east-1 aws --endpoint-url http://localhost:4566"' >> ~/.zshrc source ~/.zshrc
From now onawslocal means "run an AWS command against my local fake AWS".
About those credentialsThey are literally the word test. Your fake AWS accepts anything. Real AWS would reject them instantly — which is a useful safety net.
4

Your first command

Terminal
awslocal s3 ls
Output2026-09-23 14:40:01 meridian-cloudtrail-logs 2026-09-23 13:55:06 agentlab-public-reports 2026-09-23 14:40:01 meridian-web-assets ...
What happeneds3 is the storage service. ls lists your buckets. A bucket is just a top-level folder. Those existing ones are from other labs.
Part 3 — Doing things
5

Create a bucket

Terminal
awslocal s3 mb s3://kn-practice
Outputmake_bucket: kn-practice
Breaking it downmb = make bucket. s3:// is how you address storage, the same way https:// addresses a website.
6

Put a file in it

Terminal
echo "hello from my local cloud" > hello.txt awslocal s3 cp hello.txt s3://kn-practice/hello.txt
Outputupload: ./hello.txt to s3://kn-practice/hello.txt

Now list what is inside, and read it back without downloading it:

awslocal s3 ls s3://kn-practice/ awslocal s3 cp s3://kn-practice/hello.txt -
The trailing dashmeans "print it to my screen" instead of saving a copy.
7

Find it in the console

Browser
Where to click
Storage › hit Refresh › click the row kn-practice
Point of this stepThe terminal and the console are two views of the same thing. You made it with a command; it shows up in the UI. Use whichever is faster for the job.
Part 4 — The part that matters for security
8

Make it public

Terminal

A bucket policy is a rule about who can do what. This one says anyone can read.

awslocal s3api put-bucket-policy --bucket kn-practice --policy '{ "Version": "2012-10-17", "Statement": [{ "Sid": "AnyoneCanRead", "Effect": "Allow", "Principal": "*", "Action": "s3:GetObject", "Resource": "arn:aws:s3:::kn-practice/*" }] }'
Read that policy line by line
"Effect": "Allow"Permit, rather than deny
"Principal": "*"Who. The * means anyone at all, including people with no account
"Action": "s3:GetObject"What. Download files
"Resource": ".../*"Which files. Every file in this bucket
This one line is the breach"Principal": "*" is what turns private company data into a public website. It is the single most common cause of large data exposures, and it is exactly what you will be investigating in lab 02.
9

Read the policy back, then remove it

Terminal

This is the command you use to answer "is this bucket public?"

awslocal s3api get-bucket-policy --bucket kn-practice --query Policy --output text

Now take it away and confirm it is gone:

awslocal s3api delete-bucket-policy --bucket kn-practice awslocal s3api get-bucket-policy --bucket kn-practice
The second command should now errorAn error occurred (NoSuchBucketPolicy) ...
That error is good newsNo policy means no one has been granted anything. In this world, an error is often the answer you want.
10

Look at a different service

Terminal

Same pattern, different service. IAM is who is allowed to do what.

awslocal iam list-roles --query 'Roles[].RoleName' --output text
The shape never changesawslocal + service + action. Swap s3 for iam, sqs, dynamodb and the rest works the same way.

The --query flag trims the output to just the bit you want. Drop it to see the full response and you will understand why people use it.

12

Clean up after yourself

Terminal
awslocal s3 rb s3://kn-practice --force rm hello.txt
rb = remove bucket--force deletes what is inside first, because AWS refuses to delete a bucket that is not empty.
Build the habit hereTearing down what you created is the difference between a $3 cloud bill and a $3,000 one. It costs nothing to practise it where nothing is real.
